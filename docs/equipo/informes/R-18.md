**Qué se hizo (3 líneas):**
Se midió con Claude Code 2.1.330 (Windows, modo headless, repo descartable con remoto local) qué reglas `deny` frenan el push a `main`: 52 pruebas en seis rondas; en todas el `main` del remoto quedó intacto (`rev-parse`). Se leyó la documentación de Codex sobre `prefix_rule`. Con eso la ficha propone las reglas concretas y deja explícito qué no cubren.
Propuesta para Claude (nivel `deny`, en todos los niveles): las reglas literales de push a `main` (`origin main`, `HEAD:main`, `-u`, `--set-upstream`, `refs/heads/main`, `HEAD:refs/heads/main`, `+main`, `:main`, `--delete`), `Bash(git push)` exacto, y para `-C`/`-c` las dos exactas `Bash(git * push origin main)` y `Bash(git * push origin main *)`. Lecturas de `gh` (`pr list`, `pr diff`, `api user`) solo en `balanceado`.

**Cómo verificarlo:**
Leer las tablas de evidencia en [la ficha](../fichas/R-18.md) (cada fila trae comando, regla y motivo devuelto). Reproducir: es un repo con remoto local bare y `claude -p "<pedido>" --permission-mode default --output-format stream-json --verbose`; «has been denied» = bloqueado por `deny`, «requires approval» = ninguna regla lo cubre.

**Resultados clave**
- El `deny` por prefijo (`:*`) cubre solo las formas literales. Para `git -C <ruta>` y `git -c` el comodín con `:*` en medio **no** funciona; sí el comodín con espacio.
- `Bash(git * push origin main*)` **bloquea de más** `main-fix` y `maintenance`; las dos reglas exactas no (y siguen bloqueando `-C` y `-c`).
- `cd x && git push origin main` se evalúa por partes y se bloquea. Alias de git, `bash -c` y `git -c` con las reglas base **no** se cubren.
- Las reglas `Bash(...)` **no** aplican a la herramienta PowerShell; hacen falta reglas `PowerShell(...)`.
- Codex: la documentación describe `prefix_rule` con `decision = "forbidden"`; Windows, `git -C` y alias **no están documentados** y son experimentales. Sin Codex instalado aquí: `(TBD)`.
