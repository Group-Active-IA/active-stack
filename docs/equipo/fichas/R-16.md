Lo que dice la documentación y se usó:
- **Claude:** `hooks.<Evento>[].{matcher, hooks[].{type, command, args, timeout}}`; con `args` el comando se ejecuta «with no shell involved»; en Windows `command` debe resolver a un ejecutable real (`.exe`; `.cmd` y `.bat` no sirven); un matcher con caracteres como `(` o `|` es regex JavaScript sin anclar; las entradas de hooks se suman entre usuario, proyecto y plugins y corren en paralelo. Comentarios en `settings.json`: no documentado (por eso se rechazan).
- **Codex:** `[[hooks.<Evento>]]` y `[[hooks.<Evento>.hooks]]` con `type`, `command`, `timeout`; si una capa declara hooks en `hooks.json` y en `config.toml` carga ambos y avisa, y puede correr el mismo comando dos veces; un hook no administrado exige revisión y confianza contra su hash (`/hooks`). **No documentado:** `args`, si `command` pasa por un shell, versión mínima.
